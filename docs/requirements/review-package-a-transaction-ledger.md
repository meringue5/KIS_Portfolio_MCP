# 검토 패키지 A — 거래 원장과 과거 복원

> 상태: 승인 완료
> 기준일: 2026-08-27
> 범위: 논리 데이터 계약
> 비범위: schema, 수집 코드, backfill 실행, DB 적재, 배포

## 1. 한눈에 보는 권고안

| 결정 | 승인 내용 | 핵심 이유 |
| --- | --- | --- |
| A-1 IRP 최근구간 | 잔고 기반 provisional 상태를 만들고, 사용자 보완과 3개월 이후 과거 endpoint로 지연 reconciliation | 공통 최근구간 API는 IRP를 거부하고 전용 API에는 날짜가 없음 |
| A-2 초도 복원 | 거래내역도 3년 backfill하고, 불일치 잔여분만 `inferred_opening`으로 분리 | 비IRP 국내 현재 보유종목은 3년 주문으로 전부 수량 일치 후보 |

| A-4 미지정 매도 | 즉시 FIFO 임시 배분하되 `inferred`로 표시하고 다음 LLM 검토에서 사용자에게 확인 | 분석 연속성과 사용자 의도 보존을 함께 확보 |

A-1~A-4는 2026-08-27 모두 승인됐다.

## 2. 확인된 현황

### 2.1 국내·IRP

- 비IRP 국내 4개 계좌의 현재 보유종목 15개는 모두 3년 내 매수 근거가 있었고, 단순 수량 replay가
  현재 잔고와 일치하는 후보였다.
- IRP 현재 보유종목 7개 중 6개는 3년 내 매수 근거가 있었지만, 최근 약 3개월의 주문 이력 공백 때문에
  수량 replay를 확정할 수 없었다.
- 공통 최근구간 endpoint는 IRP를 `APBK1744`로 거부한다. 공통 이전구간 endpoint는 IRP 과거 row를
  반환하므로 거래가 약 3개월 지난 후 지연 수집할 수 있다.
- 전용 `TTTC2201R`은 날짜를 받지 않는 현재 주문상태 성격이다. 과거 backfill 원천으로 사용할 수 없다.
- 현재 잔고와 평균매입 상태는 전용 잔고 endpoint에서 확인할 수 있지만 개별 매수 사실을 복원하지 않는다.

### 2.2 미국주식

- 현재 보유종목 4개 모두 3년 주문 이력에 관련 주문이 있었고, 3개에는 매수 근거가 있었다.
- 어떤 종목도 단순 주문수량 replay만으로 현재 잔고와 완전히 일치하지 않았다. 실제 관측 주문은 보존하되
  잔여분을 opening 또는 reconciliation 대상으로 분리해야 한다.
- 3년 범위를 60일 단위로 나눈 주문 조회는 오류 없이 완료됐다. 긴 구간 조회에서는 연속조회 도중
  데이터 변경 오류가 발생했으므로 짧은 shard와 bounded retry가 필요하다.
- 해외 일별거래 39건 모두 수수료와 적용환율을 제공했다. 주문과 날짜·종목·방향·수량을 대조하면
  35건은 후보가 하나였고 4건은 후보가 없었다. 공식 order identity는 제공되지 않았다.

이 결과는 계좌번호·종목·수량·가격·금액을 출력하거나 저장하지 않은 read-only probe에서 얻었다.
수량 일치는 corporate action, 입출고 및 정정까지 검증한 회계적 확정이 아니다.

## 3. 승인된 논리 계약

### A-1. IRP 최근구간 fallback

**결정**

1. 오래된 주문은 `CTSC9215R`에서 `actual` 원천으로 지연 수집한다.
2. 아직 이전구간에 들어가지 않은 기간은 최신 잔고를 기준으로 `provisional` reconciliation 상태를 둔다.
3. 사용자가 증권사 내역을 보완하면 `manual` 근거로 기록한다.
4. 약 3개월 후 과거 endpoint에 나타난 주문과 대조하여 provisional 값을 `actual` 또는
   `reconciliation_exception`으로 정정한다.
5. 전용 현재 주문상태 API에서 관측한 row는 보존할 수 있지만 전체 과거 거래를 대표한다고 가정하지 않는다.

**대안**

- 정확한 증권사 파일을 반드시 수동 수입하기 전에는 IRP lot 분석을 제공하지 않는다. 정확성은 높지만
  초기 사용성과 자동화가 크게 떨어진다.
- 3개월을 기다린 뒤에만 lot을 만든다. 원천은 단순해지지만 최근 거래 분석이 늦어진다.

### A-2. 3년 거래 backfill과 opening 처리

**결정**

1. 가격 일봉뿐 아니라 국내·해외 거래내역도 최근 3년을 초도 backfill 범위로 한다.
2. 실제 주문 row는 각각 승인된 주문 단위 purchase lot 또는 sell event로 보존한다.
3. replay 수량과 현재 잔고가 맞고 corporate action·입출고 예외가 없으면 파생 position 상태를
   `reconstructed`로 표시한다.
4. 차이가 있으면 실제 주문을 버리지 않고 필요한 잔여수량만 backfill 시작일의 `inferred_opening`으로
   둔다. 잔여수량이 설명되지 않거나 음수가 되면 `reconciliation_exception`으로 둔다.
5. 현재 증권사 평단가는 reconciliation 근거로 사용할 수 있지만 과거의 실제 매수가격으로 소급하지 않는다.

**대안**

- 현재 보유잔고 전체를 하나의 opening lot으로 시작한다. 빠르지만 이미 확인 가능한 실제 매수 이력과
  lot별 성과를 잃는다.
- 계좌 개설 이후 전체 이력을 요구한다. 가장 완전하지만 API 보존 한도, 수작업과 초기 적재 범위가 커진다.

### A-3. 해외 수수료·환율 연결

**결정**

1. 주문체결과 일별거래 row를 서로 다른 immutable 원천 사건으로 보존한다.
2. 계좌·거래일·종목·매수매도·수량이 같고 가격·금액 허용오차까지 통과한 주문 후보가 정확히 하나일 때만
   `derived_candidate` link를 만든다.
3. candidate link는 수수료·환율 기반 분석에 사용할 수 있지만 원천 row를 병합하거나 삭제하지 않는다.
4. 후보가 없거나 둘 이상이면 자동 연결하지 않고 review queue에 둔다.
5. 이후 더 강한 공식 identity가 확보되면 link 상태를 승격하며 모든 변경 이력을 보존한다.

**대안**

- 공식 key가 없으므로 전혀 연결하지 않는다. 가장 보수적이지만 해외 lot의 실제 비용·원화 손익 계산이
  상당 부분 불가능해진다.
- 날짜·종목만 같으면 자동 연결한다. coverage는 높지만 같은 날 복수 주문에서 잘못된 비용을 붙일 수 있다.

### A-4. 매도 lot·thread 임시 배분

**결정**

1. 사용자가 지정한 lot·thread 연결을 최우선 `explicit` 근거로 사용한다.
2. thread만 지정하면 해당 thread 안의 오래된 open lot부터 FIFO로 배분한다.
3. 아무 지정이 없으면 같은 계좌·종목의 전체 open lot에 FIFO를 즉시 적용하되 `inferred`로 표시한다.
4. LLM은 다음 예약 검토에서 어떤 투자 판단을 축소·종료한 것인지 질문한다.
5. 사용자가 답하면 기존 원천 사건을 바꾸지 않고 allocation revision을 append-only로 기록한다.
6. 내부 배분 손익은 증권사 공식 평단가·실현손익·세무기록과 별도로 표시한다.

**대안**

- 사용자 답변 전까지 매도를 미배분 상태로 둔다. 의도 왜곡은 줄지만 답변이 늦으면 lot·thread 손익과
  잔여수량이 계속 미완성 상태가 된다.
- 비례 배분한다. 포지션 평균에는 가깝지만 어떤 투자 판단을 청산했는지 설명하기 어렵다.
